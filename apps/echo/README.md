# 拾言 —— Apple Watch + iPhone 个人语音记忆助手

只做**用户主动开始、状态清晰可见、参与者知情同意**的录音。不使用私有 API，不伪装成健身等其他后台任务，不隐藏系统麦克风指示。

## 可行性结论（2026-11，基于公开文档；标 ★ 的需要真机验证）

| 目标 | 结论 |
|---|---|
| 手表长时间录音 | **可行**。公开的 `UIBackgroundModes: audio`：录音必须在前台由用户发起，之后转入后台（落腕、熄屏）可继续。★ 连续数小时是否会被系统终止，需真机测 |
| 全天常驻、无感自启 | **不可行，也不做**。watchOS 不允许后台启动录音；被来电/Siri 打断后也不能在后台自动恢复，必须抬腕点「继续」 |
| 隐藏录音状态 | **不可行，也不做**。系统麦克风指示始终显示 |
| 续航 | **未知，不承诺**。AAC 16 kHz 单声道 24 kbps（硬件编码，约 11 MB/小时）。★ 需按下方方法实测 |
| 人声检测 / 降噪 | 仅做能量门限：整段（2 分钟）有声不足 2 秒才丢弃，默认关闭。它不能判断“有用信息”，嘈杂环境会全保留，极小声的对话可能被误丢——所以默认不丢。真正的 VAD 模型在手表上持续运行的功耗 ★ 未测，暂不上 |
| 离线同步 | **可行**。`WCSession.transferFile` 系统级队列，离线排队、恢复后送达；确认送达才删本地 |
| 端侧转写 | **可行**。当前用 `SFSpeechRecognizer` 端侧识别（普通话支持）。iOS 26 的 `SpeechAnalyzer` 更适合长音频，列为下一步 |
| 端侧总结 | **部分可行**。Foundation Models 需 Apple 智能；国行设备截至 2026-11 仍在随 iOS 27.3 测试版推进，代码已接入并做可用性判断。默认用规则提取（零编造） |
| 说话人区分 | **暂无**。系统没有公开的端侧说话人分离 API |
| App Store 审核 | 仅 TestFlight 自用无碍。若上架：需隐私标签、明确的录音告知；后台音频模式必须对应真实的录音功能（本 App 符合） |

## 架构

```
Apple Watch                               iPhone
Recorder  AVAudioRecorder, 2 分钟一段      PhoneSync    接收文件 → Store
   │      暂停=结束分段并释放麦克风          Transcriber  端侧转写队列 → 带时间点的句子
   ▼                                      DigestEngine 规则 / 端侧模型 / 云端(自选) → 回顾与待办
Sync      outbox 落盘 + transferFile  ──▶  Store        JSON 库 + 音频（系统数据保护）
          失败重发、重启补发                 Notifier / Exporter / AppLock
```

**防编造**：规则引擎的条目就是转写原句。模型引擎必须为每条给出来源句编号，App 校验：没有有效来源的条目丢弃；负责人、截止时间若不在来源原文中出现则清空并显示「待确认」。每条都能点开看原句并回听。

## 当前版本范围（MVP）

- 手表：开始 / 暂停 / 继续 / 结束 / 删除本次；状态、计时、电平；低电量(<10%)与存储不足自动结束并保存；系统中断自动保存；离线队列
- 手机：今日回顾（要点/决定/待办/待确认）、时间线（搜索、回听、修改、删除）、待办（勾选、确认后写入提醒事项/日历）
- 设置：暂停采集、识别语言、是否允许 Apple 服务器转写、总结引擎（含云端的告知与开关）、每日通知（默认不含内容）、App 锁、音频保留期、导出、全部删除

## 权限

| 权限 | 何时请求 | 用途 |
|---|---|---|
| 麦克风（手表） | 第一次点「开始录音」 | 录音 |
| 语音识别（手机） | 第一次有录音要转写 | 转写 |
| 通知 | 开启每日通知时 | 每日回顾提醒 |
| 提醒事项 / 日历(只写) | 第一次确认写入时 | 写入待办 |
| 面容 ID | 开启 App 锁时 | 解锁 |

## 部署

1. App Store Connect 新建 App，套装 ID 选 `com.deffisoan.echonote`（CI 首次构建会自动注册该 ID 和 `…echonote.watchkitapp`）
2. TestFlight 建内部测试组、勾自动分发、加自己
3. iPhone 在 TestFlight 安装「拾言」；手表 App 在 iPhone 的 Watch App →「可用 App」里安装（或打开自动安装）

## 真机测试清单

1. **链路**：手表录 3 分钟对话 → 结束 → 手机打开拾言，时间线出现文字，今日回顾有条目，点条目能看到原句并回听
2. **后台**：开始后落腕熄屏 10 分钟，抬腕确认计时连续、麦克风指示在
3. **离线**：手机开飞行模式录 5 分钟 → 手表显示“N 段待同步”→ 恢复后归零
4. **中断**：录音中来电 / 唤起 Siri → 提示已保存 → 点继续
5. **删除**：录音中点删除 → 手机上该次录音也消失
6. **续航**：充满电，记录电量，连续录 60 分钟（落腕），记录电量差；再测一次开着蜂窝/远离手机的情况。把两组数字发给 Claude 写回本文件
7. **长时**：连续录 3 小时，看是否被系统终止（时间线上是否有缺口）

## 提醒与实时性（v2）

- 手表本地通知（带震动）：晨间提醒可直接点「开始录音」；系统中断后 2 秒 / 3 分钟 / 10 分钟提醒继续；暂停 15 分钟提醒一次；
  录音期间挂一条 3 分钟的“看门狗”提醒并每分钟后推，App 被系统终止时它会响。★ 均需真机验证
- 分段改为 1 分钟；手机收到文件后申请后台时间做转写和增量整理（只处理新增句子并追加）。★ 后台里端侧识别/端侧模型能否稳定运行需实测
- 默认总结引擎：端侧模型可用则用它；云端可一键填 DeepSeek 预设，密钥只在 App 设置里填（存钥匙串），不要写进仓库或聊天

## 尚未解决

- 续航、连续录音上限、嘈杂环境转写准确率：均未实测
- 分段切换处有约几十毫秒的间隙，可能吞掉半个字（改用 AVAudioEngine 连续写入可消除）
- 手机 App 在后台时转写可能被系统暂停，打开 App 后继续
- 通知时间到达时不会临时生成回顾，内容以最近一次生成为准
- 存储是整库 JSON，数月数据后需换成数据库；备份为系统备份，未做独立加密口令

## 常驻助理（v3）

- **对话是主页面**：顶上是助理的头像（代码画的小白狗，会眨眼、歪头、张嘴；可在设置里换成自己的照片、改名字），回答流式显示，可中途停下。
- **DeepSeek 应用 API**（文档 api-docs.deepseek.com）：对话 `deepseek-flash`（流式、工具调用；思考模式的 `reasoning_content` 必须回传，否则带工具的多轮请求会 400）、
  搜索 `/v1/tools/search`、读网页 `/v1/tools/fetch`、语音识别 `/v1/tools/asr`（16 位 PCM WAV，≤120 秒）、语音合成 `/v1/tools/tts`（返回的 WAV 长度字段是 0xFFFFFFFF，播放前要重写文件头）、
  文件解析 `POST /files` + 对话里引用 `file_id`（PDF/Word/PPT/表格/电子书，30 天过期）。
- **语音**：点麦克风才录、界面显示计时和电平、再点发送；用语音提问时回答会读出来（可关）。
- **持续了解你**：助理会自己用 `remember` 记下长期信息（设置里可逐条删除），`forget` 纠正。
- **主动找你**：到点的事提醒（原有）+ 资讯流（上午、傍晚各一次，按话题和记忆联网整理，有内容才发）。iOS 不允许真正常驻后台，触发时机是：打开 App、系统给的后台刷新、新整理出一段、到新地点。
- **连接器**：远程 MCP（对话页「+」›「能力与连接器」）。助理自己醒来时只用标了 `readOnlyHint` 的工具。
- 密钥只在 App 里填（钥匙串），不进仓库。
- **画图**：`draw_chart` 工具（`ChartCard.swift`，Swift Charts）。模型给横轴标签和 1–4 条数据，可左右双轴；右轴数据换算到左轴范围里画。数据必须是查到的真实数字。
- **分条回复**：模型用单独一行的 `---` 把回答分成几条；每一轮（包括调用工具前说的话）都落成独立气泡，排队用打字动效放出来（`Assistant.reveal`）。图、确认卡片、来源、快捷选项挂在最后一条上。
